## Three things, one concern: the set-to-set loop at the gym
1. **Previous-set recall.** Each set row shows what was done for that same set number of that exercise in the most recent previous session, as ghost text in the inputs (for example placeholder `60` and `8`) and a quiet `Last 60 kg × 8` label in the user's display unit (`toDisp`, `wUnit`). Tapping the set's check with empty inputs logs exactly those previous values (they become real values); typed values always win. If the app already prefills last weight, extend that logic instead of duplicating it, and keep storage in kg. Cache the lookup per render, do not parse the whole log per row.
2. **Rest bar.** Replace per-exercise rest UI with ONE non-modal bar docked above the tab bar while a rest is running: remaining time large with `tabular-nums`, a thin progress line that shrinks by `scaleX`, and `−15 s`, `+15 s`, `Skip` buttons, each at least 44 x 44. It starts when a set is checked (existing duration logic), slides up 100 percent of its height over `--dur-nav` with `--ease-out`, never covers the set being logged (the screen gets bottom padding while it shows). At zero: on Android `navigator.vibrate([0, 80, 60, 80])` (feature-detected, not on iOS, not under reduced motion), the bar turns green with "Rest done" for 3 s and slides away. Deadline-based, so it stays correct across tab switches and backgrounding.
3. **Keep the screen on.** While a workout session is active (at least one set checked today and the workout not finished) and the page is visible, hold a Screen Wake Lock; re-request on `visibilitychange`; release on finish, on `pagehide`, and when no session is active. Feature-detect, fail silently, never throw on iOS versions without support.
