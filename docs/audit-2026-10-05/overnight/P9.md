## Decisions
- Operation-scoped parse snapshots first (one `JSON.parse` of `ft_logs` per render or operation), with invalidation after every write and on the `storage` event.
- Load Chart.js lazily the first time Progress needs it (inject the existing CDN script tag; keep the service worker network-first, never cache-first). If it cannot load (offline and never cached), Progress shows a calm, bounded message and every other screen still works.
- Stale search responses can never modify a newer query's results.
- Push status arriving after startup updates only its own banner and switch.
